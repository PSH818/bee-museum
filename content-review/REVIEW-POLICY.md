# 内容审校策略(现行)

> 决策日期:2026-08-24
> 背景:项目时间、能力与资金有限,无法聘请领域专家进行人工审校。

## 决策

首期采用 **AI 对抗式审查** 作为正式展出的内容门槛,以 `reviewStatus: "ai-reviewed"` 表示。
它不等同于专家审校:界面徽章统一显示 **"AI 对抗审查通过 · 未经专家核校"**,不向观众暗示存在专业审核。

## 审查机制

每条内容(观察条目 / 器官条目 / 对照行 / 蜂种记录)由三位**互不通信**的审查员独立给出结论:

| 审查员 | 职责 | 默认倾向 |
|--------|------|----------|
| 事实核查员 | 逐条抓取引用来源,核对每个断言是否被原文支持 | 未被支持即 fail |
| 反驳者 | 只负责证伪:主动搜索反例、过时说法、以偏概全、张冠李戴 | 拿不准即 uncertain |
| 合规审查员 | 科普表述合规:绝对化用语、夸大、拟人化误导、单位/数字口径、学名规范、安全暗示、入侵物种/保护等敏感表述 | 有疑即 fail |

**裁决规则**:三方全部 pass 才升级 `ai-reviewed`;任一 fail 或 uncertain 的条目保留 `draft`,记录问题并修改文案后进入下一轮复审。审查结论与修改记录落盘于 `content-review/adversarial/`,可复现、可追溯。

## 门禁

- `npm run build`:结构校验(Zod、引用完整性),draft 只警告
- `npm run build:release`:发布门禁,**任何 draft 均阻止发布**;`ai-reviewed` 及以上放行

## 升级路径

当条件允许时,专家人工核对后将条目升级为 `reviewed`/`verified`,并填写 `reviewer`/`lastReviewedOn`;界面徽章随之变为"已审校"。对抗式审查记录可作为专家审校的起点材料。
